\# Google Vector Search Collection Policy Documentation



\## Resource



Terraform resource: `google\_vector\_search\_collection`



This resource defines a Google Cloud Vector Search Collection. It controls the collection location, collection identifier, display information, labels, data schema, vector schema, and customer-managed encryption key configuration.



The main security-related argument in this resource is `encryption\_spec.crypto\_key\_name`, which allows the collection to use a Cloud KMS customer-managed encryption key. The KMS key must be in the same region as the Vector Search Collection.



\## Implemented Policies



| Policy | Terraform argument | Included / Excluded | Justification |

|---|---|---|---|

| `encryption\_spec` | `encryption\_spec.crypto\_key\_name` | Included | This argument controls the Cloud KMS key used to protect the Vector Search Collection. A policy was added to require customer-managed encryption instead of relying only on default encryption. |

| `crypto\_key\_region` | `location` and `encryption\_spec.crypto\_key\_name` | Included | The Terraform documentation states that the Cloud KMS key must be in the same region as the resource. A policy was added to detect cases where the collection region and KMS key region do not match. |

| `approved\_location` | `location` | Included | This argument controls where the Vector Search Collection is deployed. A policy was added to restrict deployment to approved regions so data is not stored in unapproved locations. |

| `sensitive\_collection\_id` | `collection\_id` | Included | This argument is used as the collection identifier. A policy was added to prevent sensitive words such as password, secret, token, credential, private, or pii from being used in the collection ID. |

| `sensitive\_data\_schema` | `data\_schema` | Included | This argument defines the data fields used by the collection. A policy was added to prevent sensitive field names such as password, token, secret, ssn, credit\_card, pii, api\_key, or private\_key from being included in the schema. |



\## Excluded Arguments



| Terraform argument | Included / Excluded | Reason for exclusion |

|---|---|---|

| `display\_name` | Excluded | This is mainly a display field. It does not directly control encryption, access, network exposure, or other strong security behaviour. |

| `description` | Excluded | This is metadata used to describe the collection. It was excluded because the current policy set already checks sensitive information in stronger places such as `collection\_id` and `data\_schema`. |

| `labels` | Excluded | Labels are useful for ownership and governance, but they do not directly enforce a security control on the Vector Search Collection. |

| `vector\_schema.field\_name` | Excluded | This defines the vector field name and is mainly functional configuration for the collection. |

| `vector\_schema.dense\_vector.dimensions` | Excluded | This controls vector dimensionality and is an ML configuration setting, not a direct security control. |

| `vector\_schema.dense\_vector.vertex\_embedding\_config.model\_id` | Excluded | This selects the embedding model. It is functional model configuration and not suitable for a general security policy. |

| `vector\_schema.dense\_vector.vertex\_embedding\_config.task\_type` | Excluded | This defines the embedding task type. It is functional configuration and does not directly affect the security posture of the resource. |

| `vector\_schema.dense\_vector.vertex\_embedding\_config.text\_template` | Excluded | This defines the text template used for embeddings. It is application-specific and not suitable for a reusable security policy. |

| `id` / `name` | Excluded | These are computed attributes generated by Google Cloud after resource creation, so they are not suitable for input policy validation. |

| `create\_time` / `update\_time` | Excluded | These are output-only timestamps and cannot be controlled directly through Terraform input policy. |

| `timeouts` | Excluded | Timeout settings control Terraform operation behaviour and do not directly affect the security posture of the Vector Search Collection. |



\## Testing Evidence



Each policy was tested using:



1\. A compliant Terraform example: `c.tf`

2\. A non-compliant Terraform example: `nc.tf`

3\. Terraform plan output converted to JSON using `terraform show -json`

4\. OPA evaluation against the generated `plan.json`



Expected result:



\- `c.tf` should pass the policy.

\- `nc.tf` should produce a policy violation message.

\- OPA output should show the violation only for the non-compliant resource.



\## Summary



The selected policies focus on encryption, KMS key region validation, approved deployment location, and prevention of sensitive information exposure in collection identifiers and data schema. Arguments that are metadata-only, ML configuration, computed values, or operational Terraform settings were excluded to avoid unnecessary or unreliable policy checks.
