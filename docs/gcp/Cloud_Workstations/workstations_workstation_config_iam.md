## 🛡️ Policy Deployment Engine: `workstations_workstation_config_iam`

This section provides a concise policy evaluation for the `workstations_workstation_config_iam` resource in GCP.

Reference: [Terraform Registry – workstations_workstation_config_iam](https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/workstations_workstation_config_iam)

---

## Argument Reference  

| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `location` | Used to find the parent resource to bind the IAM policy to. If not specified, the value will be parsed from the identifier of the parent resource. If no location is provided in the parent identifier and no location is specified, it is taken from the provider configuration. | false | false | Location is used to identify the parent workstation config for IAM binding, but this policy set does not validate approved IAM locations. | None | None |
| `workstation_cluster_id` | Used to find the parent resource to bind the IAM policy to | false | false | The workstation cluster ID helps identify the parent resource for IAM binding, but this policy set does not validate approved cluster IDs for workstation config IAM resources. | None | None |
| `workstation_config_id` |  | false | false | The workstation config ID identifies the target resource for IAM policy assignment, but this policy set does not validate approved workstation config IDs for IAM resources. | None | None |
| `project` | If it is not provided, the project will be parsed from the identifier of the parent resource. If no project is provided in the parent identifier and no project is specified, the provider project is used. | false | false | Project identifies where the IAM policy is applied, but this policy set does not validate approved project IDs for workstation config IAM resources. | None | None |
| `member/members` | Each entry can have one of the following values: * **allUsers**: A special identifier that represents anyone who is on the internet; with or without a Google account. * **allAuthenticatedUsers**: A special identifier that represents anyone who is authenticated with a Google account or a service account. * **user:{emailid}**: An email address that represents a specific Google account. For example, alice@gmail.com or joe@example.com. * **serviceAccount:{emailid}**: An email address that represents a service account. For example, my-other-app@appspot.gserviceaccount.com. * **group:{emailid}**: An email address that represents a Google group. For example, admins@example.com. * **domain:{domain}**: A G Suite domain (primary, instead of alias) name that represents all the users of that domain. For example, google.com or example.com. * **projectOwner:projectid**: Owners of the given project. For example, "projectOwner:my-example-project" * **projectEditor:projectid**: Editors of the given project. For example, "projectEditor:my-example-project" * **projectViewer:projectid**: Viewers of the given project. For example, "projectViewer:my-example-project" | false | true | IAM members should not include broad public principals because they can grant workstation config access to anyone on the internet or anyone with a Google account. | The IAM member or members list uses specific approved identities, such as user:jane@example.com. | The IAM member or members list includes broad principals, such as allUsers or allAuthenticatedUsers. |
| `role` | `google_workstations_workstation_config_iam_binding` can be used per role. Note that custom roles must be of the format `[projects|organizations]/{parent-name}/roles/{role-name}`. | false | true | IAM roles should follow least privilege. Overly broad roles can grant more access than required to workstation config resources. | The IAM policy uses an approved least-privilege role, such as roles/viewer. | The IAM policy uses an overly broad role, such as roles/owner or roles/editor. |
| `policy_data` | a `google_iam_policy` data source. | false | true | IAM policy data can define who has access to the workstation config. It should not grant access to broad public principals or unsafe identities. | The policy_data grants access only to approved identities, such as user:jane@example.com. | The policy_data grants access to broad principals, such as allUsers or allAuthenticatedUsers. |
