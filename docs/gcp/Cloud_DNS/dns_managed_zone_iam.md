## 🛡️ Policy Deployment Engine: `google_dns_managed_zone_iam_policy`
This section provides a concise policy evaluation for the `google_dns_managed_zone_iam_policy` resource in GCP.
Reference: [Terraform Registry – google_dns_managed_zone_iam](https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/dns_managed_zone_iam)

## Argument Reference  
| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `managed_zone` | Used to find the parent resource to bind the IAM policy to. | true | false | The managed zone identifier has no independent security impact at the policy level. | None | None |
| `project` | The ID of the project in which the resource belongs. | false | false | Project ID has no impact on the security of the resource or data contained. | None | None |
| `role` | The role that should be applied. Possible values include: `roles/dns.reader`, `roles/dns.peer`, `roles/viewer`, `roles/editor`, `roles/owner`. | true | true | Overly permissive roles such as `roles/owner` or `roles/editor` grant excessive privileges on DNS managed zones, violating the principle of least privilege. Only read-level or DNS-specific roles should be permitted to prevent unauthorised modification of DNS records which could lead to DNS hijacking or service disruption. | roles/viewer, roles/dns.reader, roles/dns.peer | roles/owner, roles/editor |
| `members` | Identities that will be granted the privilege in role. Can include `allUsers`, `allAuthenticatedUsers`, `user:`, `serviceAccount:`, `group:`, `domain:`. | true | false | While members could include public identifiers, the primary security control is enforced at the role level. Member identity is managed through organisational IAM policies. | None | None |
| `policy_data` | The policy data generated by a google_iam_policy data source. | true | false | Policy data is a computed field derived from role and member bindings. The security control is enforced at the role attribute level. | None | None |
