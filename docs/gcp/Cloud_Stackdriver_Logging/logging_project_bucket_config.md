## 🛡️ Policy Deployment Engine: `logging_project_bucket_config`

This section provides a concise policy evaluation for the `logging_project_bucket_config` resource in GCP.

Reference: [Terraform Registry – logging_project_bucket_config](https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/logging_project_bucket_config)

---

## Argument Reference  

| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `project` | The project that will own the logging bucket. Format: projects/PROJECT_ID | true | false | This identifies which project owns the logging bucket. It has no direct security impact on the bucket's content or access controls. | projects/my-project | None |
| `location` | The location (region or multi-region) where the logging bucket will be created. Examples: global, us-central1, eu, asia-southeast1, australia-southeast1 | true | false | Location selection affects data residency requirements and compliance (e.g., GDPR, HIPAA) but does not directly impact security controls like encryption or access management. | australia-southeast1 | None |
| `bucket_id` | The name of the logging bucket. Must be unique within the project and location. Cannot be modified after creation. | true | false | Bucket ID is a unique identifier for the resource. It has no security implications beyond being a reference name. | audit-log-bucket | None |
| `description` | An optional user-provided description for the logging bucket. Maximum length of 800 characters. | false | false | Description is metadata only and does not affect any security controls, encryption, or access policies. | Project-level logging bucket for compliance audit logs | None |
| `locked` | Whether the bucket is locked. If locked, the retention period cannot be reduced and the bucket cannot be deleted. Default: false. | false | true | Locking a bucket ensures that retention policies cannot be shortened and the bucket cannot be deleted, which is critical for compliance with legal hold requirements and audit log preservation. Once locked, the setting is permanent and cannot be undone. | true | false |
| `retention_days` | Number of days that logs will be retained in the bucket. After this period, logs are automatically deleted. Minimum: 1 day, Maximum: 3650 days (10 years). | false | true | Retention period must be sufficient for compliance requirements (CIS GCP Benchmark 2.3 recommends 30+ days for audit logs). Too short retention may result in loss of audit trails required for security investigations and compliance audits. | 90 | 15 |
| `enable_analytics` | If set to true, enables log analytics for the bucket. Log analytics provides SQL-based querying and analysis capabilities. Default: false. | false | false | Enabling analytics improves log query capabilities but does not directly impact security controls. Access to analytics features is governed by IAM permissions. | true | false |
| `cmek_settings` | Customer-Managed Encryption Key (CMEK) settings for the bucket. Configures encryption of log data at rest with a user-managed KMS key. | false | true | CMEK provides customer-controlled encryption of log data, required for compliance with HIPAA, SOC2, and PCI DSS. Without CMEK, Google-managed encryption is used which may not meet compliance requirements. | Refer to child arguments | None |
| `index_configs` | Configuration for custom log field indexing to enable efficient log queries. Indexing improves query performance but may increase storage costs. | false | false | Index configuration affects query performance and cost but does not impact security controls like encryption, access management, or data integrity. | Refer to child arguments | None |

### cmek_settings Block

| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `name` | The resource name of the CMEK settings. Format: projects/PROJECT_ID/locations/LOCATION/buckets/BUCKET_ID/cmekSettings | false | false | Name is a system-generated identifier for the CMEK settings. Has no security implications. | projects/my-project/locations/global/buckets/audit-bucket/cmekSettings | None |
| `kms_key_name` | KMS key name format: 'projects/[PROJECT_ID]/locations/[LOCATION]/keyRings/[KEYRING]/cryptoKeys/[KEY]' To enable CMEK for the bucket, set this field to a valid kmsKeyName for which the associated service account has the required cloudkms.cryptoKeyEncrypterDecrypter roles assigned for the key. The Cloud KMS key used by the bucket can be updated by changing the kmsKeyName to a new valid key name. See [Enabling CMEK for Logging Buckets](https://cloud.google.com/logging/docs/routing/managed-encryption-storage) for more information. | true | true | KMS key name determines which customer-managed key encrypts the logs. Using a valid CMEK key is required for compliance. Invalid or missing keys result in Google-managed encryption. | projects/security-project/locations/global/keyRings/logging-ring/cryptoKeys/audit-key | None |
| `kms_key_version_name` | KMS key version name format: 'projects/[PROJECT_ID]/locations/[LOCATION]/keyRings/[KEYRING]/cryptoKeys/[KEY]/cryptoKeyVersions/[VERSION]' This is a read-only field used to convey the specific configured CryptoKeyVersion of kms_key that has been configured. It will be populated in cases where the CMEK settings are bound to a single key version. | false | false | Key version name is a read-only field that identifies the specific key version. Has no security impact beyond tracking which key version is active. | projects/security-project/locations/global/keyRings/logging-ring/cryptoKeys/audit-key/cryptoKeyVersions/1 | None |
| `service_account_id` | Before enabling CMEK for a logging bucket, you must first assign the cloudkms.cryptoKeyEncrypterDecrypter role to the service account associated with the project. Use [v2.getCmekSettings](https://cloud.google.com/logging/docs/reference/v2/rest/v2/TopLevel/getCmekSettings) to obtain the service account ID. This is a read-only field. | false | false | Service account ID identifies the service account that needs KMS permissions. Has no direct security impact but is required for CMEK setup. | service-1234567890@gcp-sa-logging.iam.gserviceaccount.com | None |

### index_configs Block

| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `field_path` | Specifies the log field path to be indexed. Note that some paths are automatically indexed, and other paths are not eligible for indexing. See [indexing documentation](https://cloud.google.com/logging/docs/analyze/custom-index) for details. | true | false | Field paths determine which log fields are indexed for faster queries. This has no security implications as indexing does not expose additional data or change access controls. | protoPayload.methodName | textPayload |
| `type` | The type of data in the field. Determines how the field is indexed and queried. Valid values: TYPE_UNSPECIFIED, STRING, NUMBER, INTEGER, BOOLEAN, TIMESTAMP. | true | false | Field type helps optimize indexing and query performance but has no security implications. | STRING | TYPE_UNSPECIFIED |
