## 🛡️ Policy Deployment Engine: `logging_billing_account_sink`

This section provides a concise policy evaluation for the `logging_billing_account_sink` resource in GCP.

Reference: [Terraform Registry – logging_billing_account_sink](https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/logging_billing_account_sink)

---

## Argument Reference
| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `name` | The name of the logging sink. Must be unique within the billing account. | true | true | Sink names should clearly indicate purpose and destination to ensure proper management and auditability of log export configurations. | Descriptive names following organizational naming conventions (e.g., security-logs-to-bq, audit-logs-to-cs) | Generic or unclear names that don't indicate sink purpose or destination |
| `billing_account` | The billing account to which the logging sink applies. | true | true | Billing account selection ensures the sink is applied to the correct organizational scope and impacts cost management and access controls. | Proper billing account ID with appropriate access controls | Incorrect or unauthorized billing account |
| `destination` | Cloud Storage bucket, a PubSub topic, a BigQuery dataset or a Cloud Logging bucket. Examples: - `storage.googleapis.com/[GCS_BUCKET]` - `bigquery.googleapis.com/projects/[PROJECT_ID]/datasets/[DATASET]` - `pubsub.googleapis.com/projects/[PROJECT_ID]/topics/[TOPIC_ID]` - `logging.googleapis.com/projects/[PROJECT_ID]]/locations/global/buckets/[BUCKET_ID]` The writer associated with the sink must have access to write to the above resource. | true | true | Destination selection impacts data security, access controls, and compliance with data residency requirements. Must be properly secured destinations. | Properly secured destinations with appropriate access controls and encryption | Unsecured or unauthorized destinations, public buckets, or improperly configured endpoints |
| `filter` | The filter that determines which log entries to include in the sink. See [Advanced Log Filters](https://cloud.google.com/logging/docs/view/advanced_filters) for information on how to write a filter. | false | true | Filter criteria must ensure all required security and compliance logs are captured while avoiding unnecessary data export that could increase risk. | Comprehensive filters that capture all required security and compliance logs | Overly restrictive filters that miss critical security logs or overly broad filters that export unnecessary data |
| `description` | A description of the sink's purpose, what log data it exports, and where it sends the data. | false | true | Clear descriptions help ensure proper understanding of log data flows, destinations, and purposes for security monitoring and compliance. | Detailed description of sink purpose, data content, and destination | Missing or vague descriptions that obscure sink purposes and data flows |
| `disabled` | Whether the sink is disabled. If true, the sink does not export any log entries. | false | true | Sink status should be carefully managed to ensure critical log exports remain active for security monitoring and compliance requirements. | false (for required security and compliance log exports) | true (for sinks that should be active per security policy) |
| `bigquery_options` | Options that affect sinks exporting data to BigQuery. | false | true | BigQuery options impact how log data is stored and accessed, affecting security monitoring, query performance, and compliance. | Properly configured BigQuery options matching security requirements | Misconfigured options that impact security monitoring or compliance |
| `exclusions` | Log entries that match any of the exclusion filters are not exported. | false | true | Exclusions must be carefully configured to avoid filtering out security-critical log data while properly reducing noise. | Minimal, well-justified exclusions that don't impact security monitoring | Overly broad exclusions that filter security-relevant logs or exclusions that could mask malicious activity |

### bigquery_options Block
| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `use_partitioned_tables` | By default, Logging creates dated tables based on the log entries' timestamps, e.g. syslog_20170523. With partitioned tables, the date suffix is no longer present and [special query syntax](https://cloud.google.com/bigquery/docs/querying-partitioned-tables) has to be used instead. In both cases, tables are sharded based on UTC timezone. | false | true | Partitioned tables can improve query performance and cost efficiency but require proper query syntax and management. | true (for improved performance and cost management) | false (when partitioned tables are required for compliance or performance) |

### exclusions Block
| Argument | Description | Required | Security Impact | Rationale | Compliant | Non-Compliant |
|----------|-------------|----------|-----------------|-----------|-----------|---------------|
| `name` | The name of the exclusion. Must be unique within the sink. | true | true | Exclusion names should clearly indicate purpose to ensure proper management and auditability. | Descriptive exclusion names following naming conventions | Generic or unclear exclusion names |
| `description` | A description of the exclusion's purpose and what log entries it filters out. | false | true | Clear descriptions help ensure proper understanding of what log data is being excluded and why. | Detailed description of exclusion criteria and business justification | Missing or vague exclusion descriptions |
| `filter` | The filter that determines which log entries to exclude from the sink. | true | true | Exclusion filters must be carefully constructed to avoid excluding security-relevant logs. | Well-defined filters that exclude only non-security-relevant noise | Overly broad filters that exclude security-critical logs |
| `disabled` | Whether the exclusion is disabled. If true, the exclusion does not filter any log entries. | false | true | Exclusion status should match the intended filtering behavior for proper log export management. | Properly configured based on exclusion requirements | Misconfigured exclusion status that impacts log filtering |
